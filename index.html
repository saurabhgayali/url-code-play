URL Code

The URL is the program. Write commands in the path, share the link, and it runs — answering in plain text like an API. No editor, no runtime to install, no snippet store.

An experiment by Saurabh Gayali · MIT-spirited, self-hostable, ~one file of language.

Try it in three seconds

/print/Hello%20World          ->  Hello World
/set/x/10/add/x/20/print/x    ->  30
/repeat/3/print/ha            ->  ha, one per line
/read/example.com             ->  the page, as raw text

Features

Programs live in the URL

No database, no accounts, no saved state. The link is the entire artefact — paste it in chat, a ticket, or a README.

Plain-text, API-style output

Program URLs answer with text/plain: no HTML, no CSS, no client JavaScript, nothing to hydrate.

Server-side execution

Programs are evaluated on the server, so output is identical in a browser, in curl, or inside a CI job.

Variables and arithmetic

set, add, subtract, multiply, divide — strict left-to-right evaluation, no hidden precedence.

Repeat

repeat/<n> runs the single command that follows it n times — enough for tables, counters, and ramps.

/read as a CORS bypasser

Fetches any public URL server-side and returns raw text, so same-origin rules never block a feed, sitemap, or open JSON endpoint.

Piping with //

A double slash ends the read target; commands after it keep running and append their output beneath the fetched content.

Domain policy

blacklist.json holds a whitelist and a blacklist. A non-empty whitelist locks reads to those domains only.

Guard rails

15-second fetch timeout, 512 KB response cap with a truncation notice, and a step limit that stops runaway programs.

Inline error reporting

Unknown commands, missing arguments, and division by zero are reported as readable text at the point they occur.

Browser playground

The hosted app ships a dark terminal playground with a program field, generated URL, copy button, and clickable examples.

curl friendly

Works the same in a browser tab, a terminal, or a shell pipeline — pipe it into grep, jq, or a file.

Command reference

CommandMeaning
/print/<text>Print literal text, or the value of a variable with that name.
/set/<var>/<value>Assign a numeric or text value to a variable.
/add/<var>/<value>Add a number, or another variable's value, to a variable.
/subtract/<var>/<value>Subtract from a variable.
/multiply/<var>/<value>Multiply a variable.
/divide/<var>/<value>Divide a variable; dividing by zero is an inline error.
/repeat/<n>/<command>Run the following single command n times.
/read/<url>Fetch a public URL server-side and emit it as raw text. No https:// needed — just the domain.
/read/<url>;<command>A semicolon ends the read target and the program continues after it.

Teaching

Demonstrate evaluation order, URL encoding, and statelessness with links students can click and edit.

Quick fetching

Read an RSS feed, robots.txt, or a public JSON endpoint as text from a page that would otherwise be CORS-blocked.

Throwaway endpoints

Produce a deterministic text response for a health check, a demo, or a webhook stub — without deploying anything new.

Run it yourself

  1. Clone the repo: git clone https://github.com/saurabhgayali/url-code-play
  2. Install dependencies: npm install
  3. Start the dev server: npm run dev, then open /help
  4. Edit blacklist.json to tighten or open the /read domain policy
  5. Deploy the app in src/ to Vercel — this landing page is GitHub Pages only

FAQ

Is any of my code stored?

No. There is no database, no account, and no logging of programs. The URL is the only place a program exists.

Why does /read need a double slash?

The scheme's own // is preserved, and the next double slash marks the end of the fetch target so the rest of the path can keep executing as commands.

Can I read a private or authenticated URL?

No. Reads send no cookies, credentials, or authorization headers, and are intended for public resources only.

What happens on a blocked domain?

The response body is simply blacklisted with HTTP 403. The same wording covers both a deny-list hit and a whitelist miss, so the configuration is never leaked.
